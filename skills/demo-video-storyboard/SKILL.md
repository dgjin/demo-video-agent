# 演示视频分幕策划

把「要展示的系统」变成「能直接配音和录屏的文稿」。本技能只负责讲什么、怎么分幕；
TTS、录屏、合成与验收由 `demo-video-production` 技能完成。

## 输入与交付物

开始前先确认四件事，缺什么问什么：

1. 待演示的系统或项目，以及可访问的本地或测试地址；
2. 目标观众与最想讲清的两三个重点；
3. 成片时长预算与画幅（默认 1920×1080）；
4. 画面源类型：真实操作录屏、纯展示页、导入已有素材（真机录屏 / 实拍 / 渲染视频 / 截图序列），还是终端回放（asciinema `.cast`）。

交付物：

- `narration.md`：每幕标题 + 逐句旁白，一句话一个句号；
- 幕清单：幕 ID、幕名、画面类型（展示页 / 真实操作 / 素材导入 / 终端回放）、预估时长；
- 勘察记录：登录方式、关键选择器、每个交互点的一句话说明（素材幕不需要；终端幕只需确认要执行的命令与关键输出行）；
- 风险清单：需要登录、缓存、异步等待或涉及敏感数据的幕。

## 步骤

### 1. 现场勘察（真实操作幕必做）

按用户视角跑通一遍主路径，逐项记录：

- 登录方式与测试账号的获取方式（只记录方式，不记录口令）；
- 主界面在 1920×1080 下是否无滚动、关键按钮与输入框的选择器；
- 数据源、时间范围、标签页的默认值，以及切换后的可见变化；
- 查询或生成类操作的耗时、是否有服务端缓存；
- 哪些步骤必须等待异步结果，哪些可以并行。

把每个交互点写成一句话，例如「在数据源下拉里选择订单库，再点运行」。
这句话既是分幕草案，也是后面 `run(ctx)` 的骨架。

### 2. 设计幕结构

推荐 6–10 幕的骨架：

1. 片头：一句话说清产品与价值，不超过 25 秒；
2. 场景或问题：用户为什么需要它；
3. 核心能力 2–4 幕：每幕只讲一条主线操作；
4. 差异化：架构、治理、可移植性等能建立信任的内容；
5. 验收或闭环：结果如何被验证，质量如何保障；
6. 片尾：上手命令与行动指引，不超过 90 秒。

约束：

- 每幕只回答一个问题，幕名用名词短语，不用口号；
- 展示页、真实操作、素材导入与终端回放交替出现，避免连续三幕都是纯文字；
- 素材幕推荐一句旁白配一张截图（图片按句首自动切换）；已有视频素材按内容分段，一段一幕；
- 终端幕适合展示安装、构建或运行过程：命令输出控制在 20 行内，旁白逐句对应关键输出，不要逐行念；
- 终端幕的 cast 时长应与旁白接近（制作侧会按 `cast / (旁白 × 0.92)` 自动倍速，0.7×–1.5× 内最自然）；
- 幕间不重复问候，新增开场幕后检查后续幕是否语义重叠；
- 总时长按 6–12 分钟设计，系统演示超过 15 分钟通常需要拆片。

### 3. 撰写旁白

写作规则：

- 每幕 15–90 秒，单句不超过 40 字，一句话一个句号，VTT 按句切分；
- 数字口头化，写「一百二十万」而不是「1,200,000」；
- 术语全片统一，首次出现时用半句话解释；
- 删掉「大家好」「接下来我们」「话不多说」这类空转句；
- 每个交互点用一句话预告、一句话确认结果；
- 只用演示数据，不写真实客户名、业务数字、账号或令牌；
- 需要强调的数字与文案，必须能在画面同一时刻找到对应元素。

### 4. 估算时长

中文 edge-tts 在默认 `-4%` 语速下约每秒 4.2–4.8 个字（含标点停顿），
按每秒 4.5 字估算即可。估算只用于分幕取舍，成片时间轴以配音后的
`audio/durations.json` 为准。英文、日文等多语言配音按对应语言的正常语速估算。

### 5. 交棒检查

交付前逐项确认：

- 幕 ID 与 `config.scenes` 一一对应，建议从 `m00` 连续编号；
- 每幕至少一句，每句以句号结尾，没有跨句的长段落；
- 真实操作幕都标注了交互点，且选择器已在勘察中验证；
- 终端幕的 `.cast` 已录制，命令输出为行式（不含 vim/top 这类全屏界面）；
- 旁白提到的数字、按钮名、文件名与画面一致；
- 文稿保存为项目根目录的 `narration.md`，编码为 UTF-8。

## 文稿模板

下面是一份可直接改用的最小示例，格式即最终格式：

```markdown
## m00 · 片头（约 12s）

这是一个把分幕文稿自动做成演示视频的插件。
写清楚要讲什么，剩下的交给流水线。

## m01 · 核心流程（约 20s）

流水线只有四个环节。
写稿、配音、录屏，最后合成。
每一幕的时长，都以真实音频为准。

## m02 · 片尾（约 10s）

安装插件，运行 init 生成项目。
把你的文稿交给它，就能得到成片。
```

标题行固定为「## 幕 ID · 幕名（约 X 秒）」；括号内是预估时长，
配音后会被真实时长替换，不需要手工维护。

## 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 单幕超过 120 秒 | 想把多个观点塞进一幕 | 按「一个观点一幕」拆分 |
| 旁白很满但画面很空 | 先写文案后想画面 | 删掉无法在画面落地的句子 |
| 观众记不住重点 | 每幕信息密度过高 | 一屏一个观点，数字不超过三个 |
| 配音后节奏拖沓 | 书面语与长句 | 改短句，删修饰词，再重新配音 |
| 画面与旁白错位 | 用字数估算时间轴 | 交给制作技能，按 VTT 句首校准 |

## 与制作技能的分工

- 本技能产出 `narration.md`、幕清单与勘察记录；
- `demo-video-production` 负责建项目、TTS 配音、画面设计、录屏、合成与抽帧验收；
- 文稿改动后只需重跑受影响幕的配音与录屏，不必整片重来。
